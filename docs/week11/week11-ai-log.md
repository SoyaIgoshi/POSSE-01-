# Week11 AIと考えたログ

## Part 1：AIと考えた1セッション

### テーマ

GitHub User FinderのJavaScriptコードについて、`fetch()`、`response.ok`、`response.json()`、`await`がそれぞれ何をしているのか、なぜ必要なのかを理解する。

### 送った指示（良いプロンプトの型）

目的:
GitHub User FinderのJavaScriptコードについて、`fetch()`、`response.ok`、`response.json()`、`await`がそれぞれ何をしているのか理解したい。

前提:
JavaScriptの基本的な文法やfetch()はある程度理解しているが、APIからデータを取得して画面に表示するまでの流れを、自分の言葉で説明することにはまだ自信がない。

見てほしい観点:
`fetch()`、`response.ok`、`response.json()`、`await`がそれぞれ何をしているのか、また、なぜこの順番で使っているのかを確認したい。

制約:
完成したコードを新しく作るのではなく、現在のコードの意味や処理の流れを中心に説明してほしい。

出力形式:
それぞれについて「何をしているか」「なぜ必要なのか」の2点に分けて、初心者にも分かるように説明してほしい。

### 返ってきた出力（要約）

AIから、`fetch()`はAPIにリクエストを送ってレスポンスを受け取るために使い、`await`によってレスポンスが返ってくるまで待っていると説明された。

また、`response.ok`はHTTP通信が成功したかを確認するために使い、エラーの場合は処理を止めてエラーメッセージを表示するために必要だと分かった。

`response.json()`は、レスポンスのJSONデータをJavaScriptで扱えるデータに変換する処理であり、その結果を`data`として受け取って画面表示に利用していることが分かった。

### "なぜ"を聞いた記録

* 聞いたこと:

`response.json()`をなぜ使う必要があるのか？

* 返ってきた説明（要約）:

APIから返ってくるレスポンスは、そのままではJavaScriptでデータとして扱うことができないため、`response.json()`を使ってJSON形式のデータをJavaScriptで扱える形に変換する必要があると説明された。

* 聞く前は分からなかったが、聞いて分かったこと:

以前は`response.json()`はAPIを使うときに決まって書くものだと思っていた。しかし、APIから返ってきたレスポンスと、実際にJavaScriptで使うデータは別のものだと分かった。`response.json()`によってデータを取り出しているから、その後に`data.name`や`data.followers`のようにデータを利用できることを理解した。

### 出力の4分類

| 採用する  | `response.json()`はレスポンスのJSONデータをJavaScriptで扱える形に変換する処理である。 | 実際のコードで`const data = await response.json()`として取得したデータを、その後`data.name`や`data.followers`などで使用しているため。 |
| 保留する  | HTTPステータスコードの種類を詳しく覚えること。                                  | 今回の課題ではAPI通信の基本的な流れを理解することが目的なので、ステータスコードの細かい種類まで覚える必要はないと判断した。                                    |
| 採用しない | `response.ok`が`404`のときだけtrueになるという説明。                      | `response.ok`は404だけを判定するものではなく、HTTPレスポンスが成功したかどうかを表すものなので、今回のコードの理解には適切でないと判断した。                   |
| 要確認   | APIから返ってくるJSONデータの詳しい構造や、JSONとJavaScriptオブジェクトの違い。         | 今回の説明だけでは詳しい違いを完全には判断できないため、必要になったら公式ドキュメントなどで確認したい。                                               |

## Part 2：過去のAI利用を振り返る

### AIの出力をそのまま採用してしまった経験

以前の課題でAIにコードを作ってもらったとき、コードが動いたので、そのまま採用してしまったことがあった。そのときは一部の処理について、なぜその書き方をしているのかを十分に理解できていなかった。

今回、AIに「なぜこの処理が必要なのか」を質問することで、コードが動くことだけでなく、処理の意味まで理解することが重要だと分かった。

## Part 3：これからのAIルール

### 学んだこと

AIはコードを作ったり説明したりするのに便利だが、回答をそのまま正しいと思うのではなく、自分で理由を説明できるか確認することが重要だと学んだ。

### 自分のAIルール

1. AIからコードをもらったら、まず「なぜこの書き方なのか」を質問して理解する。
2. AIの回答をそのまま採用せず、自分でコードを動かして確認する。
3. 分からない内容は「採用する・保留する・採用しない・要確認」に分け、自分で判断する。
4. 個人情報やパスワード、APIキーなどの機密情報をAIに送らない。
